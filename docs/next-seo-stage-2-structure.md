# Этап 2. Выбор структуры миграции

Дата решения: 2026-05-16.

## Выбранный вариант

Next.js версия будет создана в отдельной папке внутри текущего репозитория:

```text
next/
```

Текущий Vite-проект остается на месте и продолжает жить в корне репозитория до полной проверки Next.js версии.

## Почему так

- Это самый безопасный путь для поэтапной миграции: текущий сайт можно собирать и проверять как раньше.
- Next.js приложение можно поднимать, переносить страницы и тестировать независимо.
- Не нужно сразу менять существующие `src`, `public`, `index.html`, `vite.config.ts` и Vite-скрипты.
- Меньше риск сломать текущую публикацию или потерять юридические страницы, отзывы, оплату и страницы экскурсий.

## Планируемая структура

```text
.
├── src/                    # текущий Vite frontend, временно остается как есть
├── public/                 # текущие публичные файлы Vite
├── next/                   # новое Next.js приложение
│   ├── app/
│   ├── src/
│   │   ├── components/
│   │   ├── config/
│   │   ├── data/
│   │   └── assets/
│   ├── public/
│   ├── package.json
│   ├── next.config.ts
│   └── tsconfig.json
└── docs/
```

Внутри `next/` будет отдельный `package.json`, чтобы не смешивать зависимости Vite и Next на этапе переноса. Общие данные (`tours`, `reviews`, `contacts`, `navigation`) на первом проходе будут скопированы в `next/src`, а после стабилизации можно решить, нужен ли общий пакет или перенос корневого проекта.

## Команды после инициализации

Команды будут запускаться из `next/`:

```bash
npm run dev
npm run build
npm run start
npm run lint
```

Корневые команды Vite временно сохраняются:

```bash
npm run dev
npm run build
npm run preview
```

## Что не делаем на этом этапе

- Не удаляем Vite-файлы.
- Не переносим backend `mm-mail`.
- Не меняем `.env` и секреты.
- Не меняем текущую структуру `src/` в корне.
- Не переключаем production на Next.js до прохождения всех этапов проверки.

## Следствие для этапа 3

На этапе 3 нужно инициализировать Next.js приложение в `next/` с TypeScript и App Router, затем проверить:

- базовый запуск dev server;
- production build;
- отсутствие TypeScript ошибок;
- что текущий Vite build по-прежнему не сломан.

## Статус проверки

- Решение по структуре принято.
- Место Next.js приложения определено: `next/`.
- Текущий Vite-проект остается рабочим fallback.
