# Этап 11. Оптимизация изображений и скорости

## Что сделано

- Найдены тяжелые изображения в `next/src/assets`: основные фото весили от 1.6 МБ до 8.7 МБ.
- Для изображений тяжелее 800 КБ созданы WebP-копии рядом с исходниками.
- Next-импорты переключены с тяжелых `.jpg`/`.png` на `.webp` там, где эти копии используются в страницах и компонентах.
- `SmartImage` теперь использует `next/image` для локальных `StaticImageData`, а внешние URL оставляет обычным `<img>`.
- Убрано `unoptimized` у hero-изображения.
- Верхние `PageBanner` получают `priority`, `fetchPriority="high"` и `sizes="100vw"`.
- Портрет в блоке ниже первого экрана переведен на lazy loading.

## Результаты сжатия

- `kremlin.png`: 8686 КБ -> `kremlin.webp`: 301 КБ.
- `pocket.jpg`: 4381 КБ -> `pocket.webp`: 446 КБ.
- `detail.jpg`: 4078 КБ -> `detail.webp`: 373 КБ.
- `uslugi.jpg`: 4019 КБ -> `uslugi.webp`: 353 КБ.
- `overview.jpg`: 3405 КБ -> `overview.webp`: 278 КБ.
- `pay.jpg`: 3207 КБ -> `pay.webp`: 314 КБ.
- `rew.jpg`: 2912 КБ -> `rew.webp`: 153 КБ.
- `meet2.jpg`: 2859 КБ -> `meet2.webp`: 127 КБ.

Полный набор WebP-копий для тяжелых экскурсионных и служебных фото находится в `next/src/assets`.

## Проверка

- `npm run lint` в `next` проходит.
- `npm run build` в `next` проходит.
- В `.next/static/media` нет файлов тяжелее 800 КБ.
- Самый тяжелый файл production media после сборки - 466 КБ.
- Общий размер файлов в `.next/static/media` после сборки - около 9.25 МБ.
- HTML `/tours` содержит `_next/image` URL, значит локальные изображения проходят через оптимизацию Next.

## Примечания

- Исходные `.jpg` и `.png` оставлены в репозитории как запасные оригиналы, но больше не импортируются в Next-страницы, где есть WebP-замены.
- Отзывы, `home-hero.jpg` и `guide-portrait.jpg` не пересжимались: они уже меньше 500 КБ.

## Итог

Этап 11 выполнен: тяжелые изображения заменены на легкие WebP-версии, локальные изображения проходят через `next/image`, production build остается рабочим.
